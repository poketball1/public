# 사장 모드

사용자가 `사장모드` 또는 `사장 모드`를 요청했을 때 적용한다.
main은 목표·설계·경계·위험 수용·최종 보고를 소유하고, 직원은 맡은 범위의 산출물을 만든다.
이 스킬은 설치한 프로젝트의 `CLAUDE.md`/`AGENTS.md`와 사용자의 권한·모델 선택을 따른다.
과거 특정 모델의 은퇴 일정이나 AIR 내부 전용 도구를 전제로 하지 않는다.

## 범위와 팀 구성

착수할 때 요청 결과, 수정해도 되는 표면, 보존할 경계, 완료 증거를 정한다.
아키텍처 변경은 해당 프로젝트의 owning contract와 기존 결정을 먼저 확인한다.
작은 작업은 main이 직접 처리하고, 독립 조사·구현·반복 적용·검증은 경계가 잡힌 직원에게 맡긴다.
직원 호출 자체는 수정·외부 적용·위험 수용 권한을 추가하지 않는다.

- 한 번에 끝나는 작업: 현재 harness의 직원 도구를 사용한다.
- 여러 직원의 결과를 합치고 후속 round를 지휘하는 작업: Codex를 작은 사장으로 발주할 수 있다.
  하위 위임이 실제 활성화된 환경인지 확인하고, 깊이와 쓰기 범위를 packet에 적는다.
- 설계 선택이 갈리고 다른 관점이 다음 결정을 바꿀 때: 사용자의 모델·자문 정책 안에서
  별도 검토를 구한다. 검토자는 main의 승인·완료 권한을 대신하지 않는다.

Claude에서 Codex를 호출할 때는 같은 프로젝트에 설치한 `/codex-bg`를 사용한다.
모델과 추론 설정은 해당 환경의 설정을 승계하며, 사용자가 지정한 값을 임의로 교체하지 않는다.
Codex 아래에서 다시 Claude background 직원을 실행하는 체인은 완료 회수 경로가 확인된 경우에만 쓴다.

## 위임 packet

한 직원에게 하나의 계약과 완료 기준을 준다. 값이 여러 파일을 건너면 마지막 소비자까지
연결 확인의 소유자를 지정한다. 서로 다른 직원이 같은 파일을 수정하면 호환 가능한 hunk로 나눈다.

```text
Goal: 사용자가 얻을 결과
Authority: 읽을 계약·기존 결정과 정확한 파일 경로
Owned scope: 읽기/쓰기 범위와 다른 직원의 소유 범위
Hard walls: 금지 행동과 사용자에게 돌아올 결정
Inputs: 필요한 자료, 알려진 미결 사항
Verification: 실행할 명령, 정상·실패 경로의 기대 효과
Return: 변경 파일, 원문 증거 경로, 검증 결과, 요구사항별 처분
Stop: 결정 충돌·권한 부족·범위 밖 변경이 필요한 조건
```

직원은 다른 작업의 변경을 되돌리지 않는다. 기준이 부족하면 추측으로 범위를 넓히지 않고
원문·후보·부족한 근거를 돌려준다. 완료하지 못한 요구는 성공 보고 속 위험 목록에 숨기지 않는다.

## 실행과 회수

각 위임의 목적, task/thread ID, 산출물 경로를 기록한다. independent 작업이 있으면 진행하고,
없으면 harness의 대기·완료 알림 기능을 사용한다. 잦은 상태 조회로 대기를 대체하지 않는다.
완료 알림과 복구 절차는 `/codex-bg`의 실행 기록 계약을 따른다.

같은 문제의 후속 구현은 명시적 thread로 resume해 맥락을 사용한다. 독립 감리는 fresh thread로
시작한다. 살아 있는 작업에 다른 작업을 중복 발주하기 전에 현재 상태와 남은 효과를 확인한다.

## 검수와 마감

직원 보고는 초안이다. main은 요구 목록이 소진됐는지, 근거가 실제 파일·명령 결과와 맞는지,
사용자나 다음 소비자에게 결과가 도달했는지 확인한다. process 성공과 작업 완료를 구분한다.

runtime·권한·복구·여러 직원의 통합에 correctness가 달리면 독립 감리로 완료 주장을 검토한다.
발견 사항은 main이 판정하고 수리·명시적 미완료로 처분한다. 수정 후에는 변경분과 파급 범위를
다시 검증한다. 결정에 영향을 주는 발견이 없으면 불필요한 round를 추가하지 않는다.

마감에는 문서·설치 경로·기존 변경 보존·검증 누락도 확인한다. 최종 보고는 사용자 관점의 결과,
변경 파일, 검증, 남은 한계와 감리 여부를 담는다. 직원의 green 보고가 최종 완료를 대신하지 않는다.
